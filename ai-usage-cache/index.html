Summary

結論を先に：利用枠は「毎回送り直される入力」で溶ける

① 会話は毎回ぜんぶ送り直される 基本

モデルは前の会話を覚えていない。50 回目の入力では 49 回分の履歴がまるごと再入力される。履歴が不要なら新しいセッション、質問は1 回の入力にまとめる。

② キャッシュ＝先頭が同じなら再計算しない 仕組み

2 回目以降、先頭から同じ位置にある文章は前回の計算結果を再利用できる。キャッシュ読み取りは通常入力の約 1/10（Fable 5.1 は 1/40）の価格。

③ キャッシュを切らさない 3 原則 実践

  • 先頭からの位置を変えない（/compact 乱用しない）
  • 時間を空けすぎない（Claude Code は 1 時間）
  • 途中でモデル・effort・サブエージェント構成を変えない

ChatGPT の使い分け

調べ物は上限が緩いチャットで、資料化はワークで。デスクトップアプリの @ でチャット履歴をワークに渡せる。

Claude の使い分け

長いドキュメントはプロジェクト機能にアップロード。ナレッジはキャッシュされ、再利用時は制限にカウントされない（公式ヘルプ）。

ツール呼び出しを減らす

ツール 1 回＝モデル入力 +1 回。MCP はツールサーチの往復も増える。不要な MCP を外す・effort を下げる。

Basics ① · 動画 01:03–03:02

1 つのセッションで会話を続けない

濃い紫＝今回の入力、薄い紫＝過去の入力の再送。ターンが進むほど 1 回あたりの入力が長くなる。

何が起きているか

  • AI モデルは前の会話を保持できない。「こんばんは」と打ったとき、内部では「こんにちは」とその返答も含めた全部が入力として渡されている。
  • 1 つのセッションで会話を続けると、処理してもらう文字数が毎回増えていく。50 回やり取りすれば 50 回目は 49 回分の履歴を再送している。

対策

  • これまでの履歴を参照しなくても問題ないなら、すぐ新しいセッションを開く。
  • 教えている中で実際にあった例：1 つの会話でずっと使い続けて利用枠が溶けていた。

Cache · 動画 10:13–12:40

キャッシュとは：「先頭から同じ位置」の入力を 2 回目以降は再計算しない

難しいことを抜きにすると

  • AI モデルに2 回以上、先頭から同じ位置で入力した場合に使える機能。
  • 2 回目の入力では「こんにちは」を処理するための計算結果を再利用できるので、少ない計算量で処理できる。
  • 細かくは「何文字以上ないとキャッシュされない」などの条件もあるが、押さえるべきは先頭から同じ ＋ 2 回以上の 2 点。

どこで使えるか

ChatGPT ワーク、Codex、Claude Code のいずれもこの仕組みを使う。どういう場合にキャッシュが効いて、どういう場合に切れるかを理解して使えば消費を抑えられる。

Rule ① · 動画 14:20–16:30

原則①：/compact を頻繁にやると、かえって消費が増える

compact とは

それまでの会話履歴を要約して短くする操作。Claude Code でも ChatGPT ワークでも使え、/compact と入力すると「セッションを圧縮しました」と出る。

なぜ逆効果になりうるか

  • 要約に置き換わると先頭からの入力情報が変わるので、入力や返答のキャッシュが切れる。
  • compact 自体がそれまでのセッションを入力して処理するので、その分も消費する。

示唆

履歴が不要なら compact より新しいセッション。使うなら頻繁にではなく区切りで。

Rule ② · 動画 16:31–18:00

原則②：時間を空けすぎない（キャッシュライフタイム）

仕組み

  • キャッシュは Anthropic や OpenAI のサーバー側で一時的に保管されるだけで、保管期間は無制限ではない。
  • 一定時間入力がないとクリアされる。これがキャッシュライフタイム。

実務上の注意

  • 作業後 1 時間ほど放置して同じセッションで再開すると、それまでの全セッション分がキャッシュなしで送られる。
  • 時間を空けて再開するときは「キャッシュが切れているかもしれないが、それでも続きからやりたいのか」を考える。

補足（要約者注）：Claude Code 公式ドキュメントでは、サブスクリプションのプラン内利用でメイン会話が 1 時間、API キーや利用クレジット消費時は 5 分がデフォルト。詳細は姉妹スライド「Claude Code のトークン使用量と削減策」を参照。

Tools · 動画 22:21–25:00

ツールを使う回数をなるべく減らす

ポイント 1：ツールの分だけ入力回数が増える

「ユーザー入力 → 出力」ではなく、ツール実行の結果をまたモデルに入力する。その度にそれまでの入力も再送されるので、ツールを使いすぎると消費も時間も増える。

ポイント 2：effort レベルが高いとツールを多用する

effort を「高」「最大」にすると、頑張ってツールをたくさん使ってタスクをこなそうとする → 呼び出し回数が増える → 入力が膨らむ。

対策

  • 無駄な MCP はなるべく使わない・接続しない
  • 速度や利用枠がネックなら effort を下げる
