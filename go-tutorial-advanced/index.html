A · Accessing a relational database (3/4)

複数行を読む・1 行を読む：Query / QueryRow と Scan

やってみよう

右の 2 関数を main.go に追加し、main の末尾に下の呼び出しを足して go run .。

main に追加 albums, err := albumsByArtist("John Coltrane") if err != nil { log.Fatal(err) } fmt.Printf("Albums found: %v\n", albums) alb, err := albumByID(2) // ID 2 を直書きして試す if err != nil { log.Fatal(err) } fmt.Printf("Album found: %v\n", alb) $ go run . Albums found: [{1 Blue Train John Coltrane 56.99} {2 Giant Steps John Coltrane 63.99}] Album found: {2 Giant Steps John Coltrane 63.99}

ポイント

  • プレースホルダ ? に引数を渡す。文字列連結で SQL を組み立てない（SQL インジェクション防止）。
  • rows.Next() → rows.Scan(&…) で 1 行ずつ構造体に写す。defer rows.Close() と最後の rows.Err() を忘れない。
  • QueryRow は 1 行専用。該当なしは sql.ErrNoRows。エラーは fmt.Errorf で「どの関数で・何のキーで」を付けて返す。
func albumsByArtist(name string) ([]Album, error) { var albums []Album rows, err := db.Query("SELECT * FROM album WHERE artist = ?", name) if err != nil { return nil, fmt.Errorf("albumsByArtist %q: %v", name, err) } defer rows.Close() for rows.Next() { // Scan で列を構造体のフィールドへ var alb Album err := rows.Scan(&alb.ID, &alb.Title, &alb.Artist, &alb.Price) if err != nil { return nil, fmt.Errorf("albumsByArtist %q: %v", name, err) } albums = append(albums, alb) } if err := rows.Err(); err != nil { return nil, fmt.Errorf("albumsByArtist %q: %v", name, err) } return albums, nil } func albumByID(id int64) (Album, error) { var alb Album row := db.QueryRow("SELECT * FROM album WHERE id = ?", id) err := row.Scan(&alb.ID, &alb.Title, &alb.Artist, &alb.Price) if err != nil { if err == sql.ErrNoRows { return alb, fmt.Errorf("albumsById %d: no such album", id) } return alb, fmt.Errorf("albumsById %d: %v", id, err) } return alb, nil }

C · Getting started with generics (1/2)

同じ処理を型ごとに書く → 型パラメータで 1 つにする

やってみよう

  1. generics ディレクトリで go mod init example/generics。
  2. まず SumInts と SumFloats（非ジェネリック）と main を書いて go run .。
  3. SumIntsOrFloats を追加し、main に 型引数を明示した呼び出しを足して go run .。

読み方

  • [K comparable, V int64 | float64] が型パラメータ。K は「== で比較できる型」、V は int64 か float64 のどちらか（union）。
  • 本体は同じコード。var s V のように型パラメータをそのまま型として使う。
  • 呼び出し側で SumIntsOrFloats[string, int64](ints) と型引数を与えると、コンパイル時にその型で具体化される。
  • map のキーは比較可能である必要があるので comparable 制約が要る。
generics/main.go（抜粋）func SumInts(m map[string]int64) int64 { var s int64 for _, v := range m { s += v } return s } func SumFloats(m map[string]float64) float64 { var s float64 for _, v := range m { s += v } return s } // SumIntsOrFloats sums the values of map m. It supports both int64 and float64 // as types for map values. func SumIntsOrFloats[K comparable, V int64 | float64](m map[K]V) V { var s V for _, v := range m { s += v } return s } func main() { ints := map[string]int64{"first": 34, "second": 12} floats := map[string]float64{"first": 35.98, "second": 26.99} fmt.Printf("Non-Generic Sums: %v and %v\n", SumInts(ints), SumFloats(floats)) fmt.Printf("Generic Sums: %v and %v\n", SumIntsOrFloats[string, int64](ints), SumIntsOrFloats[string, float64](floats)) } $ go run . Non-Generic Sums: 46 and 62.97 Generic Sums: 46 and 62.97

やってみよう

  • Go 1.27 ではメソッドにも型パラメータを書けるようになった。

ここでの狙い

  • 単体テストは人間が思いついた入力しか検証しない。3 ケースは通るが、この Reverse には バグが 2 つある（バイト単位で反転している）。
  • ファジングは入力を機械的に変異させて大量に流し、panic や「性質」の破れを探す手法。Go 1.18 から go test に標準搭載。
  • テーブル駆動テスト（構造体スライスをループ）は Go の定番の書き方。
fuzz/main.gopackage main import "fmt" func main() { input := "The quick brown fox jumped over the lazy dog" rev := Reverse(input) doubleRev := Reverse(rev) fmt.Printf("original: %q\n", input) fmt.Printf("reversed: %q\n", rev) fmt.Printf("reversed again: %q\n", doubleRev) } func Reverse(s string) string { b := []byte(s) for i, j := 0, len(b)-1; i < len(b)/2; i, j = i+1, j-1 { b[i], b[j] = b[j], b[i] } return string(b) } fuzz/reverse_test.gofunc TestReverse(t *testing.T) { testcases := []struct{ in, want string }{ {"Hello, world", "dlrow ,olleH"}, {" ", " "}, {"!12345", "54321!"}, } for _, tc := range testcases { rev := Reverse(tc.in) if rev != tc.want { t.Errorf("Reverse: %q, want %q", rev, tc.want) } } }

D · Getting started with fuzzing (2/3)

ファズテストに書き換えて、1 つ目のバグを見つける

やってみよう

  1. reverse_test.go を右の FuzzReverse に置き換える（unicode/utf8 を import）。
  2. go test → シードコーパスだけで走り PASS。
  3. go test -fuzz=Fuzz → 数秒以内に FAIL。失敗入力が testdata/fuzz/FuzzReverse/ に保存される。
  4. 保存されたファイルを cat して中身を見る。

読み方

  • FuzzXxx(f *testing.F)。f.Add でシードコーパス、f.Fuzz にランダム入力を受ける関数を渡す。
  • 期待値は書けないので性質で検証する：「2 回反転すると元に戻る」「有効な UTF-8 を渡せば結果も有効」。
  • 失敗入力はファイルに残り、以後 go test だけでも毎回再実行される＝回帰テストに自動で昇格。
fuzz/reverse_test.gofunc FuzzReverse(f *testing.F) { testcases := []string{"Hello, world", " ", "!12345"} for _, tc := range testcases { f.Add(tc) // Use f.Add to provide a seed corpus } f.Fuzz(func(t *testing.T, orig string) { rev := Reverse(orig) doubleRev := Reverse(rev) if orig != doubleRev { t.Errorf("Before: %q, after: %q", orig, doubleRev) } if utf8.ValidString(orig) && !utf8.ValidString(rev) { t.Errorf("Reverse produced invalid UTF-8 string %q", rev) } }) } $ go test -fuzz=Fuzz fuzz: elapsed: 0s, gathering baseline coverage: 3/3 completed, now fuzzing with 8 workers fuzz: minimizing 41-byte failing input file --- FAIL: FuzzReverse (0.03s) --- FAIL: FuzzReverse (0.00s) reverse_test.go:20: Reverse produced invalid UTF-8 string "\xb5\xc4" Failing input written to testdata/fuzz/FuzzReverse/123f558d22cc0d86 To re-run: go test -run=FuzzReverse/123f558d22cc0d86 FAIL $ cat testdata/fuzz/FuzzReverse/123f558d22cc0d86 go test fuzz v1 string("ĵ") ← 2 バイト文字。バイト単位で反転すると壊れる

  3. 修正 2：入力が不正な UTF-8 なら error を返す（右下）。main とファズテストも 2 値を受けるよう直す。
  4. go test -fuzz=Fuzz -fuzztime 30s → 30 秒回して PASS。
$ go test -fuzz=Fuzz # 修正 1 の後 --- FAIL: FuzzReverse (0.01s) reverse_test.go:17: Before: "\xdb", after: "�" Failing input written to testdata/fuzz/FuzzReverse/a2f306083e514b06 $ go test -fuzz=Fuzz -fuzztime 30s # 修正 2 の後 fuzz: elapsed: 0s, gathering baseline coverage: 5/5 completed, now fuzzing with 4 workers fuzz: elapsed: 3s, execs: 80290 (26763/sec), new interesting: 12 (total: 12) … fuzz: elapsed: 30s, execs: 1172817 (30281/sec), new interesting: 17 (total: 17) PASS ok example/fuzz 31.025s

学び：Go の string はバイト列で、有効な UTF-8 とは限らない。[]rune 変換は不正なバイトを U+FFFD に置き換える。ファジングは「人間が想定しない入力」を機械的に持ってくる。

修正 1：rune 単位で反転func Reverse(s string) string { r := []rune(s) for i, j := 0, len(r)-1; i < len(r)/2; i, j = i+1, j-1 { r[i], r[j] = r[j], r[i] } return string(r) }
修正 2：不正な UTF-8 はエラーにする（"errors", "unicode/utf8" を import）func Reverse(s string) (string, error) { if !utf8.ValidString(s) { return s, errors.New("input is not valid UTF-8") } r := []rune(s) for i, j := 0, len(r)-1; i < len(r)/2; i, j = i+1, j-1 { r[i], r[j] = r[j], r[i] } return string(r), nil } ファズテスト側（f.Fuzz の中） rev, err1 := Reverse(orig) if err1 != nil { return } // エラーは対象外として続行 doubleRev, err2 := Reverse(rev) if err2 != nil { return }

E · govulncheck (1/3)

脆弱な依存をわざと入れて、govulncheck を用意する

やってみよう

  1. vuln-tutorial で go mod init vuln.tutorial、右の main.go（golang.org/x/text/language を使う）を書いて go mod tidy。
  2. わざと古い版に下げる：go get golang.org/x/text@v0.3.5。
  3. go install golang.org/x/vuln/cmd/govulncheck@latest（$(go env GOPATH)/bin に入る）。
  4. go run . en-US ja xx-zz でプログラムが動くことを確認。

使うもの

  • govulncheck：Go チーム提供の脆弱性検査ツール。データ源は Go 脆弱性データベース（GO-YYYY-NNNN 形式の ID）。
  • golang.org/x/text v0.3.5 の language.Parse には既知の脆弱性（GO-2021-0113、範囲外読み取りで panic）がある。
  • go get pkg@version は依存の版を上下どちらにも動かせる。
vuln-tutorial/main.gopackage main import ( "fmt" "os" "golang.org/x/text/language" ) func main() { for _, arg := range os.Args[1:] { tag, err := language.Parse(arg) if err != nil { fmt.Printf("%s: error: %v\n", arg, err) } else if tag == language.Und { fmt.Printf("%s: undefined\n", arg) } else { fmt.Printf("%s: tag %s\n", arg, tag) } } } $ go mod tidy $ go get golang.org/x/text@v0.3.5 go: downgraded golang.org/x/text v0.42.0 => v0.3.5 $ go install golang.org/x/vuln/cmd/govulncheck@latest $ go run . en-US ja xx-zz en-US: tag en-US ja: tag ja xx-zz: error: language: subtag "xx" is well-formed but unknown

E · govulncheck (2/3)

検査する：自分のコードが実際に呼ぶ脆弱性だけが「affected」になる

やってみよう

  1. govulncheck ./... を実行。
  2. 出力の Example traces found にある main.go:12:29 が、自分の language.Parse 呼び出しの位置と一致することを確認。
  3. govulncheck -show verbose ./... で「import しているだけ」の脆弱性も見てみる。

結果の読み方

  • Symbol Results：モジュールの版だけでなくコールグラフを解析し、自分のコードから脆弱な関数に到達するものだけを「affected」として、そのコールスタックを示す。
  • import しているだけ・require しているだけのものは件数のみ（下段）。直すべきものが明確で、版番号だけで判定する一般的な SCA ツールより誤検知が少ない。
  • 「Fixed in」の版以上に上げれば解消する。

修正して再確認、エディタと CI に組み込む

やってみよう

  1. go get golang.org/x/text@v0.3.8（「Fixed in」以上の版へ。実務では最新に）。
  2. govulncheck ./... → No vulnerabilities found.

VS Code Go からの利用（Tutorial 10）

  • go.mod を開き、コマンドパレットで Go: Toggle Vulncheck → 依存の脆弱性が診断として表示される。
  • 行にホバーで概要、電球（Quick Fix）から run govulncheck to verify でコールスタック解析、Upgrade で修正版へ更新。
  • 裏で gopls が govulncheck を呼んでいる。設定は Vulnerability scanning in IDEs。

CI に入れる

GitHub Actions なら golang/govulncheck-action、または go install …/govulncheck@latest && govulncheck ./... を 1 ステップ追加。バイナリに対して govulncheck -mode=binary ./app も可。

②応用編で通ったこと

  • DB：sql.Open は接続しない、Ping で確認。プレースホルダで渡し、Scan で構造体へ。認証情報は環境変数。
